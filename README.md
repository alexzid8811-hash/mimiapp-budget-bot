# Telegram Budget Mini App — MVP

Мини-приложение для Telegram под схему бюджета **зарплата / аванс / обязательные платежи / дневной лимит / автоматический буфер / ручная копилка**.

По умолчанию создаются две границы бюджетного периода:

- зарплата — **7 число**;
- аванс — **22 число**.

Если 7-е или 22-е приходится на нерабочий день по производственному календарю РФ для пятидневной рабочей недели, фактическая дата выплаты автоматически переносится на **последний рабочий день перед ним**. Именно фактическая дата выплаты становится границей бюджетного периода.

Пример: если 7 февраля выпадает на субботу, период начинается 6 февраля. Если 22 февраля выпадает на воскресенье, аванс считается полученным 20 февраля, в пятницу.

Суммы пользователь задаёт в настройках.

## Что работает

- несколько ежемесячных доходов;
- зарплата и аванс как границы финансовых периодов;
- автоматический перенос зарплаты/аванса на предыдущий рабочий день по производственному календарю РФ;
- дополнительные разовые доходы;
- обязательные ежемесячные платежи по сумме и дню месяца;
- категории расходов;
- быстрый ручной ввод расходов;
- сумма «можно сегодня»;
- бюджет и остаток текущего периода;
- автоматический пересчёт дневного лимита после каждой траты;
- отметка обязательного платежа как оплаченного без двойного уменьшения дневного бюджета;
- прогноз будущих финансовых периодов;
- отдельная вкладка «Буфер» с расчётом по периодам: получено, обязательные платежи, дневной лимит, сколько отложить и сколько взять;
- автоматический виртуальный буфер для будущих кассовых разрывов;
- отдельная ручная копилка с пополнением, снятием и историей операций;
- резервная копия настроек и данных, включая отпускные и движения копилки;
- серверная проверка Telegram `initData`;
- SQLite, Docker и простой polling-бот с кнопкой открытия Mini App.

## Производственный календарь РФ

Для 2025 и 2026 годов в проекте есть локальные официальные исключения производственного календаря, поэтому расчёт не зависит от внешнего API.

Для следующих лет приложение пытается получить пятидневный производственный календарь РФ через `isdayoff.ru`. Если календарь будущего года ещё не опубликован или сервис временно недоступен, используется резервный расчёт по субботам/воскресеньям и федеральным праздникам. После появления официального календаря он будет использован после перезапуска приложения.

Правило переноса применяется к границам зарплаты/аванса. Даты обязательных платежей самостоятельно не переносятся.

## Как считается бюджет

1. Определяется фактическая дата ближайшей зарплаты/аванса. Если номинальная дата нерабочая, она сдвигается назад до последнего рабочего дня.
2. Текущий период определяется между фактическими датами получения доходов, отмеченных как «граница бюджетного периода».
3. Складываются регулярные доходы периода и внесённые дополнительные доходы.
4. Вычитаются все обязательные платежи периода.
5. Прогнозируются следующие периоды. Для каждого считается `доходы - обязательные платежи`.
6. Если впереди возникает накопленный структурный дефицит, часть свободных денег текущего периода автоматически блокируется в виртуальной копилке.
7. Из оставшегося бюджета вычитаются обычные расходы.
8. Остаток делится на число дней до следующей фактической границы периода включительно — это «можно сегодня».

Формула текущего свободного бюджета:

```text
бюджет периода = регулярные доходы
               + дополнительные доходы
               + возврат из резерва
               - обязательные платежи
               - автопополнение резерва

остаток = бюджет периода - обычные расходы
можно сегодня = остаток / оставшиеся дни периода
```

Обязательные платежи уже зарезервированы в расчёте. Поэтому отметка «оплачено» записывает операцию в историю, но не вычитает её второй раз из свободного бюджета.

## Локальный запуск

Требуется Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
cp .env.example .env
```

Переменные `.env` сами по себе Python не подхватывает. Для простого локального запуска достаточно:

```bash
export DEV_MODE=true
export DATABASE_PATH=./data/budget.sqlite3
uvicorn app.cashflow_app:app --reload --port 8000
```

Откройте `http://localhost:8000`.

### Docker

```bash
DEV_MODE=true docker compose up --build web
```

Приложение будет на `http://localhost:8000`.

## Подключение к Telegram

1. Создайте бота через `@BotFather` и получите `BOT_TOKEN`.
2. Разместите веб-приложение на **HTTPS**-домене. Для временной локальной проверки можно использовать HTTPS tunnel.
3. Задайте переменные:

```bash
export BOT_TOKEN="..."
export MINI_APP_URL="https://your-domain.example"
export DEV_MODE=false
```

4. Запустите web и bot:

```bash
docker compose up --build
```

5. Напишите боту `/start` и нажмите «Открыть бюджет».

Frontend отправляет `Telegram.WebApp.initData` в заголовке `X-Telegram-Init-Data`. Backend проверяет HMAC-SHA256 подпись и `auth_date`; данные из `initDataUnsafe` для авторизации не используются.

## Важное про буфер и копилку

**Буфер** рассчитывается автоматически. Это виртуальное резервирование внутри приложения, а не реальный банковский перевод: деньги исключаются из доступного бюджета, но физически остаются на вашем счёте.

**Копилка** ведётся вручную. Пополнение копилки уменьшает деньги, доступные для обычных трат, снятие возвращает их в бюджет. Приложение хранит отдельный баланс и историю этих движений.

В следующей версии можно добавить Telegram-уведомления перед платежами, графики расходов, экспорт CSV/Excel, цели накоплений и подтверждение фактического получения зарплаты.
