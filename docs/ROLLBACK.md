# Откат исправлений логики (октябрь 2026)

Как вернуть код и данные к состоянию до исправлений: гонки «Сверх максимума в день», оплаты платежа после удаления категории и цикла утренних отчётов.

## Что меняет обновление

Код:

- расчёт «Сверх максимума в день» записывает пополнение копилки под блокировкой, по одному на день;
- удаление категории переносит её и в версиях плана, а «Оплачено» больше не отказывает из-за удалённой категории;
- утренние отчёты: сбой у одного пользователя не останавливает остальных, недоставляемый отчёт (бот заблокирован) не повторяется каждую минуту, длинный список трат сокращается до 25 строк.

Данные меняются один раз, при первом запуске новой версии web или bot, и только там, где есть что исправлять:

1. Если «Сверх максимума в день» за один день записан в копилку дважды, лишняя запись удаляется. Остаётся одна, её сумму пересчитывает следующий расчёт. Добавляется уникальный индекс `ux_piggy_cap_excess`.
2. В версиях плана (`plan_history`) платежу с удалённой категорией ставится его текущая категория или «без категории».

Другие данные не меняются.

## Резервные копии

**Код.** Ветка [`backup-before-logic-fixes-2026-10-23`](https://github.com/alexzid8811-hash/mimiapp-budget-bot/tree/backup-before-logic-fixes-2026-10-23) — это `main` до исправлений, коммит `0416c3a`.

**Данные перед обновлением.** Остановите сервисы и скопируйте каталог `data/` целиком:

```bash
docker compose stop
cp -a data data-before-logic-fixes-2026-10-23
docker compose up -d --build
```

**Данные, которые исправляет приложение.** Перед изменением файла пользователя новая версия сама делает его согласованную копию:

```
data/backups/<дата-время>Z-before-repair/<telegram_id>.sqlite3
```

В логе web или bot об этом есть строка «Данные пользователя N будут исправлены; копия до исправления: …». Если такой папки нет, исправлять было нечего. Каталог `data/backups/` не попадает в git.

## Откат кода

- Изменения ещё в pull request — просто не сливайте его: `main` не тронут.
- Pull request уже слит — нажмите Revert на его странице в GitHub (или `git revert -m 1 <merge-коммит>`), затем на сервере:

  ```bash
  git pull
  docker compose up -d --build
  ```

- Быстро, прямо на сервере:

  ```bash
  git fetch origin
  git checkout backup-before-logic-fixes-2026-10-23
  docker compose up -d --build
  ```

## Нужно ли откатывать данные

Обычно нет: старая версия работает с исправленными файлами. Единственное отличие — индекс `ux_piggy_cap_excess`. Со старым кодом параллельные запросы, которые раньше задваивали запись, получат ошибку на одном из запросов (повторное открытие экрана её снимает). Чтобы убрать индекс:

```bash
docker compose stop
python3 - <<'EOF'
import glob, sqlite3
for path in glob.glob("data/users/*.sqlite3"):
    con = sqlite3.connect(path)
    con.execute("DROP INDEX IF EXISTS ux_piggy_cap_excess")
    con.commit()
    con.close()
EOF
docker compose up -d
```

## Вернуть файл пользователя из копии

Файл вернётся целиком на момент копии: всё, что пользователь записал после неё, пропадёт. Возвращайте файл только вместе с откатом кода, иначе новая версия при запуске снова его исправит.

```bash
docker compose stop
mkdir -p data-after-repair && cp -a data/users/123.sqlite3* data-after-repair/   # текущее состояние, на всякий случай
rm -f data/users/123.sqlite3-wal data/users/123.sqlite3-shm
cp "data/backups/<папка>/123.sqlite3" data/users/123.sqlite3
docker compose up -d
```

Здесь `123` — Telegram ID пользователя. Файлы `-wal` и `-shm` нужно удалить: они относятся к заменяемому файлу и испортили бы восстановленный.
